## 二、Free Credit 场景完整修复

### 2.1 场景识别（inferCategory）

**问题**：只识别英文关键词，漏识别西班牙语、无 URL 的纯 @handle 邮件等情况。

**修复**：
- 加入西班牙语 `cr[eé]ditos?` 关键词
- 新增规则：任意 `@handle`（负向后行断言排除邮件地址）直接判为 `free_credit`，无需信用积分关键词
- 新增规则：social media URL + 积分关键词联合判定
- 最终规则：`hasAtHandle || (hasCreditKeyword && hasSocialUrl)`

### 2.2 LLM 引擎 free_credit 预检

**问题**：DeepSeek 不了解 `free_credit` 这个内部业务概念，将西班牙语积分邮件归类为 general。

**修复**：在 `analyzeThreadDeepSeek` / `analyzeThreadOpenAI` 函数入口加预检——先跑 mock engine，若返回 `free_credit` 直接返回，跳过 LLM 调用。`generateDraft` / `refineDraft` 同理：category 为 `free_credit` 时全程走 mock。

同时在 LLM system prompt 中补充七个场景定义，降低其他场景的误判率。

### 2.3 截图识别修复

**问题一**：`normalizeStructuredThread` 将文章的 `attachments` 字段丢弃，导致 `classifyArticleAttachments` 永远拿不到附件列表。

**修复**：`helpers.js` 中为每篇文章保留 `attachments: cleanArray(article?.attachments)`。

**问题二**：截图文件名为通用格式（如 `Screenshot_2026-05-07_140748.png`），不含 "youtube"，被归为 `ambiguousImages` 而非 `youtubeScreenshot`。

**修复**：新增推断逻辑——`ambiguousImages + youtubeIds.length > 0` → 推断为 YouTube 截图，同时设 `screenshotNeedsVerification: true` 标志，在 Next Step 中提示客服手动核查截图。

### 2.4 YouTube handle 提取 bug 修复

**问题**：`@[\w.]{2,}` 会将邮件地址中的 `@gmail.com` 误识别为 YouTube handle。

**修复**：改为 `(?<!\S)@[\w.]{3,}`，负向后行断言排除邮件地址中间的 `@`。

### 2.5 `responses is not defined` 运行时错误

**问题**：`suggestTemplateFromStructuredData` 中引用了未定义的 `responses` 变量（遗留死代码），导致所有非 free_credit / cancel_renewal 场景在 mock 引擎下抛出运行时错误。

**修复**：删除涉及 `responses` 的五个 if 块，这些分支已被下方的 `category` 判断完全覆盖。

### 2.6 Spreadsheet row 独立字段

将表格记录行从 `next_step` 文本内嵌移出，作为独立的 `spreadsheet_row` 字段返回。面板新增专用 textarea（默认隐藏，有数据时显示），点击全选，粘贴至 Excel/Google Sheets 自动分列。

## 四、订单查询重构

### 4.1 解析错误根因

`getPrimaryDetailText` 使用 `.replace(/\s+/g, " ")` 将所有换行压平为单行，导致"每条订单两行格式"被破坏，原有正则越界捕获相邻订单的数据。

**修复**：
- `extractTextWithLineBreaks`：通过 DOM 操作（替换 `<br>` 和 block 元素）在 DOMParser 文档中保留换行，避免依赖 `innerText`（未渲染文档不可靠）
- `parseOrderRowsFromDetailBlocks`：改为行解析——按 `\n` 分割，逐行匹配 header 格式，取下一行作为订单数据行，彻底消除跨条目误捕

### 4.2 客户邮箱丢失

**问题**：`normalizeStructuredThread` 未保留 `customer_email`、`customer_id_email`、`customer_email_candidates` 字段，`extractFreeCredit` 无法获取邮箱，spreadsheet row 邮箱列为空。

**修复**：`helpers.js` 中为三个邮箱字段补充正常化逻辑。

**问题二**：发件人邮箱在 Znuny DOM 中存于 `.Sender .SortData` 的 `value` 属性（格式 `Name <email>`），`innerText` 和 `mailto:` 链接均无法获取。`collectPageEmailCandidates` 因此漏掉发件人邮箱。

**修复**：`content.js` 中加入 `.Sender .SortData` 来源，通过 `extractEmailsFromText` 提取并经 `filterCustomerEmails` 过滤。

### 4.3 Order Search Cache 移除

缓存机制导致邮箱修改后仍返回旧结果，与新增的"手动修改邮箱重新查询"功能冲突。全部移除：删除两个 TTL 常量、三个缓存变量（`orderSearchContextCache`、`orderSearchResultCache`、`orderSearchContextPromise`）、四个缓存函数及所有相关逻辑。

## 六、UI 重设计（feat/ui 分支）

### 设计方向

参考 Toggl Track 视觉风格：Space Grotesk 字体、珊瑚红主色 `#E01E5A`、淡紫灰底色、白卡片+微阴影、pill 形按钮、大写小字母 label。

### 主要变化

| 改动 | 说明 |
|------|------|
| 字体 | Segoe UI → Space Grotesk（Google Fonts） |
| 主色 | `#145af2` 蓝 → `#E01E5A` 珊瑚红 |
| 按钮 | 方形 → pill 形（`border-radius: 999px`） |
| 工具链接 | card 内 details → 顶部横向 pill 链接栏 |
| Config / Debug | 默认展开 → 折叠到底部 |
| Email Thread | 全时显示 → 默认折叠（减少干扰） |
| Analysis 区 | 四张独立卡片 → 一张带分割线的合并卡片 |
| Refine / Copy | 独立卡片 → 移至 Reply Instructions 下方 |

### 结构化订单卡片

将 Manual Lookup Result 的 textarea 替换为结构化卡片展示：
- 卡片背景按状态上色：PAID 绿、CANCEL 黄、REFUND 红
- Order ID 并入 meta 行（日期 · 供应商 · 金额 · 订单号）
- License Key 独立行，带 Copy chip（点击复制，1.5s 后显示 ✓ 反馈）
- 保留"原始数据"切换按钮，可回到 textarea 手动编辑
- 字号整体上调至 14px（基础），label 11px，pre 13.5px
